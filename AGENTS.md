# AGENTS.md — VELORA

Non-obvious notes for anyone (human or agent) working in this repository.

## Running it in the Base44 sandbox

```bash
docker compose -f docker-compose.base44.yml up -d --build
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/
```

- The app is a **static React + Vite storefront**. There is no database, API service, or
  external credential — do not add compose services for infrastructure that does not exist.
- `docker-compose.base44.yml` runs `node:22` with the repo bind-mounted at `/app` and the Vite
  dev server on container port 3000 (mapped to host 3000, the sandbox preview port).
- `node_modules` is a **named volume**, not part of the bind mount. Dependencies are installed on
  container start (`npm ci` when `package-lock.json` exists, otherwise `npm install`). A plain
  `docker compose restart web` re-runs that install step, which is what you want after editing
  `package.json`.
- `package-lock.json` is generated by the first container boot. Commit it once it exists.

### Sandbox-only overrides

| Override | Where | Why |
| --- | --- | --- |
| `allowedHosts: ['.' + BASE44_SANDBOX_HOST_DOMAIN]` | `vite.config.js` | The preview proxy sends `Host: 3000-<sandbox id>.$BASE44_SANDBOX_HOST_DOMAIN`, and the sandbox id rotates. The wildcard covers every id; an exact host would break on re-import. |

Both are gated on `process.env.BASE44_PREVIEW_MODE === '1'`:

- **`BASE44_PREVIEW_MODE=1`** (sandbox): the wildcard host allowlist applies, so the proxied
  preview host is accepted.
- **unset or any other value** (local dev / production build): the option is left `undefined`, so
  Vite's own default allowlist applies and behaviour is unchanged from a stock Vite project.

No other application configuration is overridden. The preview proxy handles iframe headers and
cookie attributes; this app sets no CSP, frame or cookie policy of its own.

## How the app is put together

- **Catalog is code, not a CMS.** `src/data/products.js` is the single source of truth (id, slug,
  prices, colours with per-colour galleries, sizes with availability, stock, rating). Every page —
  listings, PDP, cart, search, recommendations — reads from it. Add a product there and it appears
  everywhere.
- **Shared swatches.** Reuse an entry from `SWATCHES` when adding a colour; do not type a hex
  inline, or filter swatches and product swatches will drift apart.
- **Currency.** `price`/`originalPrice` are authoritative **USD**; other currencies are display
  conversions with illustrative rates in `src/lib/currency.js`. Never treat a converted amount as
  an order total.
- **State.** `src/lib/store.jsx` holds cart, wishlist, currency, toasts and the global overlays.
  Cart lines capture their USD unit price when added, so the drawer, cart page and checkout can
  never disagree about a line total. Persistence is `localStorage` only — passwords and payment
  details are never stored.
- **No payments, no auth backend, no orders.** `Checkout` is a labelled demo (validates, charges
  nothing), `Account` is a labelled device-local demo, and reviews/newsletter are sample data. Keep
  that language intact when editing those screens: do not claim a charge, an order, or a stored
  subscription happened.
- **Images.** `src/components/ui/Media.jsx` renders a reserved aspect box with `srcset`, lazy
  loading and a text fallback if a photo fails. Photography is Unsplash-hosted; ids in
  `src/data/products.js` were each verified to resolve. Add new ids only after checking they return
  200.
- **Sold-out products.** `stock: 0` drives the "Sold Out" chip on cards, disables the size buttons
  and the add-to-cart button, and makes the "In stock only" listing filter meaningful.

## How to verify a change

- `curl http://localhost:3000/` returns the Vite dev-server HTML (unhashed `/src/main.jsx` module
  script) — if you see a minified bundle instead, the preview is serving a production build and the
  edit loop is broken.
- Routes: `/`, `/shop`, `/product/:slug`, `/collections`, `/collections/:slug`, `/new-arrivals`,
  `/sale`, `/search?q=`, `/cart`, `/checkout`, `/account`, `/wishlist`, `/blog`, `/blog/:slug`,
  `/pages/:slug` (`about`, `contact`, `privacy`, `terms`, `shipping-returns`, `size-guide`, `faq`).
- End-to-end flows worth driving after a change: add to cart from
  `/product/essential-oversized-hoodie` (bag badge increments), open the size guide modal, switch
  the detail tabs, filter and sort on `/shop`, then check the cart page totals against the drawer.
